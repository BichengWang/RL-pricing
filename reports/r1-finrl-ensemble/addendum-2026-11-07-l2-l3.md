# R1 pre-registration addendum — 2026-11-07: L2 and L3 analysis

Written before any L2 or L3 run. No licensed data is on any machine yet
(P0.6); the only executions of the L2 pipeline are smoke runs on synthetic
prices with a few dozen training steps, made to test the scripts. This file
settles what [`preregistration.md`](preregistration.md) leaves open for L2
and L3, in the way [`addendum-2026-11-07.md`](addendum-2026-11-07.md) does for
L1. The claims, thresholds, verdict rules, arms and seeds do not change, and
neither file above is edited.

## 1. Runs

`evidence/l2_runs.py` runs §5.2's plan through `rl.autotrain.r1`, one
process per run with one BLAS thread: first the prefix check (arm A, seed 0,
ended on 2020-05-08), then arms A and B at seeds 0–4, then 5–9, then arm C at
0–4. Arms A and B trade the stated universe of §2.3; arm C trades the
shipped list (WBA for GE). The price file comes from `rl.marketdata.sharadar`
with the ticker map recorded in the evidence; it and the run directories
stay local.

If the prefix check differs from the long run, L2 uses separate runs ended on
2020-05-08 (§5.2) and `evidence/l2.py` refuses to score until they exist. A run
that fails is rerun with the same seed and the failure is reported.

## 2. Windows

L2: the account values from 2016-01-04 to 2020-05-08, 1,094 returns. L3: the
values from the 2020-05-08 close to 2025-12-31, so the first return is
2020-05-11's (§5.3). The toolkit records one value per session, so sessions
and returns coincide; annual return uses that count.

## 3. Baselines

- **DIA and `^DJI`** come from Yahoo's chart API at the URLs of
  `evidence/fetch_inputs.py`, fetched again by `evidence/l2.py`. Yahoo re-bases
  adjusted closes at every dividend, so the files' hashes differ from those
  of 2026-10-25 in `evidence/hashes.json` while their returns do not; the
  summary records the hash of the copy used.
- **Min-variance and 1/N** are recomputed from the runs' price file on arm A's
  30 names with `rl.trade.baselines` (min-variance: 252 trailing returns,
  re-estimated every 63 sessions, next-open fills, 0.1% per side, as §5.2
  states).

## 4. The best agent

For `ens-sharpe-vs-agents` the best standalone agent is chosen once per
level, by seed-mean Sharpe on the observed series, and stays fixed in every
bootstrap resample.

## 5. Crash windows

The crash dates are the peak and trough of `^DJI`'s largest peak-to-trough
fall inside each level's window, from the Yahoo series: 2020-02-12 to
2020-03-23 for L2 (as in §6) and 2022-01-04 to 2022-09-30 for L3 (fetched
2026-11-07). The threshold is half of DIA's own fall between those dates. The
interval and p-value come from the within-window bootstrap of the L1
addendum §4 (mean block `round(m^(1/3))` for `m` returns in the window).

## 6. Inference details

- Holm adjustment over the seven gap tests of each level.
- Arms B and C: seed-mean differences from arm A over the seeds both arms
  finished, with the same date draws applied to both, 95% percentile
  intervals. No verdict (§7).
- Deflated Sharpe with N = 3 (arms A, B, C); the variance of the trials'
  Sharpe ratios is the variance of the per-session Sharpe over every run of
  the three arms in the level's window.
- Sharpe over the T-bill (§6, secondary): FRED DTB3, the rate known at the
  previous session, accrued as rate / 252 per session. The same definition is
  applied to L1, times the number of sessions a return spans.
- Share of sessions in cash (§11) is measured as sessions with unchanged
  equity, as R0 did.

## 7. What is published

`evidence/l2/summary.json` holds metrics, intervals, verdicts and picks. It
holds no prices and no account values; the equity curves are published only
if the owner confirms that the Sharadar licence allows it (§12).
