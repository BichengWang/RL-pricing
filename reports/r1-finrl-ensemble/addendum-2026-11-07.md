# R1 pre-registration addendum — 2026-11-07: L1 analysis

Written before any full run of the authors' code. At the time of writing the
only L1 execution is the 2026-10-25 build probe (five A2C steps), and no
account value of the authors' method has been produced by us. This file
settles choices for L1 that [`preregistration.md`](preregistration.md) leaves
open or states inexactly. The claims, thresholds, verdict rules and L2/L3
design do not change, and the pre-registration is not edited.

## 1. Dates of the authors' account values

The pre-registration (§3.1, §6) concatenates the 18 files
`results/account_value_trade_ensemble_<i>.csv` and dates them with the code's
`unique_trade_date`, as `backtesting.ipynb` does. Reading
`env/EnvMultipleStock_trade.py` and `model/models.py` at the pin gives the
exact meaning of each row:

- Window *k* trades the 63 sessions `unique_trade_date[63(k+1) : 63(k+2)]`,
  called d0 to d62.
- Row 0 of each file is `previous_total_asset`: the previous window's d62
  value (for the first window, the $1,000,000 start at 2016-01-04). Rows 1
  to 62 are the values at the closes of d1 to d62.
- The value at d0 of windows 2 to 18 is never recorded. Holdings do not
  change between the previous d62 and d0, so the return from row 0 to row 1
  is the true two-session return.

So the notebook's positional dates are right for rows 1 to 62, and row 0
carries the previous close forward onto d0 as a zero return. Dropping the 17
seam rows (§6) leaves **1,117 values from 2016-01-04 to 2020-07-06; 1,078 of
them are on or before 2020-05-08, giving 1,077 returns**, 17 of which span two
sessions. §8's "1,094 daily returns" counted the seam rows. The bootstrap's
mean block stays `round(1077^(1/3))` = 10.

## 2. Annual return

`(V_T / V_0)^(252/n) - 1` uses n = trading sessions from the first to the last
value date (1,094 to 2020-05-08), not the 1,077 returns, so that the 17
two-session returns are not annualised as one day each. Sharpe and volatility
use the 1,077 returns as §6 defines them.

## 3. The L1 baseline

The DJIA for L1 is the authors' `data/^DJI.csv` (price index, `Adj Close`),
as §5.1 says; DIA total return is the L2/L3 baseline. For the gap tests the
DJIA is taken on the ensemble's 1,078 value dates, so both series are paired
date by date. The DJIA's own Table II quantities on every session of the
window are reported beside them (§3.3).

## 4. Bootstrap details

- Path statistics (cumulative and annual return, maximum drawdown) are
  recomputed on the path compounded from each resample's returns, as Sharpe
  is.
- **`ens-crash-2020`.** Resampling dates across the whole window would remove
  the crash the claim is about. Its interval and p-value come from the same
  stationary bootstrap applied only to the returns from the DJIA's peak
  (2020-02-12) to its trough (2020-03-23): 27 returns, mean block
  `round(27^(1/3))` = 3, 10,000 resamples, seed 0, one draw of dates shared by
  every run and the DJIA. The threshold stays `c_d` = half the DJIA's own
  crash drawdown on those dates, computed once from the observed series.
- Multiplicity: L1 tests five gaps (`ens-sharpe`, `ens-cumulative-return`,
  `ens-annual-return`, `ens-max-drawdown`, `ens-crash-2020`). Holm adjustment
  is over these five. `ens-sharpe-vs-minvar` and `ens-sharpe-vs-agents` are
  not tested at L1: the authors' repository has no min-variance code, and its
  ensemble loop keeps no account for the standalone agents.

## 5. Runs that do not finish

L1 runs on GitHub-hosted runners (`.github/workflows/r1-l1.yml`, mode `full`)
with a 355-minute job limit. A run that fails or times out is reported with
its reason and replaced by a new run; the L1 set is the first five runs that
finish. The runs are unseeded, so a replacement is not a choice among
results.

## 6. Picks

The pick per quarter is rebuilt from each run: the log prints the A2C and PPO
validation Sharpe ratios; the DDPG ratio is recomputed from
`account_value_validation_<i>.csv`, which DDPG writes last in each window;
the code's rule (§2.2) picks. Table I of the paper (arXiv 2511.12120v1, p. 6)
lists, for the 18 quarters in order:

PPO, DDPG, DDPG, PPO, PPO, A2C, PPO, DDPG, PPO, DDPG, A2C, A2C, DDPG, PPO,
PPO, A2C, A2C, A2C.

Agreement is counted per run against this list and between runs.
