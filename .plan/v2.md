# v2.0.0: modern policies on stronger instruments

Decided 2026-11-01 ([`decisions.md`](decisions.md)). v2 adds 2025–2026 RL and
LLM methods as entrants and re-test targets, and fixes the instrument gaps a
major version is for. It does not change any running pre-registration: R1–R3
keep their pinned code paths, tasks and entrants.

Evidence behind the choices (primary sources, read 2026-11-01): FinRL-DeepSeek
([arXiv 2502.07393](https://arxiv.org/abs/2502.07393), MIT code) is the one
2025 LLM-plus-RL trading paper with runnable training code. Trading-R1's
official repository holds only a "releasing soon" README; Fin-R1 publishes
weights but not its training scripts. DreamerV3, diffusion actors and
distributional offline RL have no verified trading results. Lookahead recall
probes ([arXiv 2512.23847](https://arxiv.org/abs/2512.23847)) and dated models
([arXiv 2603.11838](https://arxiv.org/abs/2603.11838)) make contamination
audits concrete. No LLM is trained in v2: LLMs enter only as frozen API agents
in the ledger.

## Contracts shared by the milestones

- **Execution authority.** Every new policy emits long-only target weights to
  the existing engine. No method brings its own fills, fees or accounting.
- **Records.** Schema 2 adds `protocol_version: "2"` and
  `code: {package_version, git_commit, code_sha256}` to historical, live and
  ledger records and to `freeze.json`. `code_sha256` hashes the source files
  of the policy's module and of `rl/bench/` it imports, sorted by path.
- **Information.** A policy reads text and events only through
  `MarketView.info`; an item is visible only if its timestamp is before the
  decision close of the session. Nothing else in a policy may read a clock
  or the network during `act`, except ledger entrants through their declared
  tools.
- **Trials.** Every configuration tried for a submission counts in `trials`,
  including abandoned ones.
- **Compute.** Every new reference submission fits on a CPU GitHub runner
  within the bench job's limit at default settings.
